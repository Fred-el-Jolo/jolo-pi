# Sources

Every source this skill draws on, with what each contributed. All consulted while building the skill.

## Primary sources (the four requested)

1. **Jen Bergren — "Documentation: How to write a clear business process anyone can follow"**
   https://www.jenbergren.com/blog/documentation-how-to-write-a-business-process
   - The "write it like a recipe" framing; small, atomic steps.
   - Writing rules: second person ("you"), role titles not names, no jargon, write for someone who's never done it.
   - User-testing your own steps; living-document mindset; naming as "How to…" / a question.
   - → feeds Phase 2A and [frameworks.md](frameworks.md) "Bergren writing rules".

2. **Slite — "What is process documentation? The ultimate guide and template"**
   https://slite.com/learn/process-documentation
   - Goal: repeatability & consistency; process lives in heads and breaks when people leave.
   - Distinction between *process documentation*, *SOP*, and *process map* (scope & format).
   - The hard part is maintenance: one owner, last-reviewed date, drift detection.
   - → feeds the "When to use" framing and Phase 3 (owner/cadence).

3. **IT Glue — "How to Write Process Documentation" (10 steps)**
   https://www.itglue.com/blog/how-to-write-process-documentation/
   - The 10-step model: identify → scope → boundaries → inputs/outputs → organize steps → roles → visualize → exceptions → controls → publish & test.
   - Emphasis on **documenting exceptions** and **setting controls**.
   - → mapped into the phases in [frameworks.md](frameworks.md); exceptions became Phase 2 Q2P.5.

4. **Lucid — "The basics of documenting and analyzing your as-is process"**
   https://lucid.co/blog/as-is-process-analysis
   - As-is vs to-be; why current-state comes first.
   - Research → Document → Analyze phases; data-collection methods (interviews, observation, surveys).
   - BPMN 2.0 as the standard notation.
   - → feeds the as-is stance, Phase 4 validation, and the BPMN note in [frameworks.md](frameworks.md).

## Supplementary sources

5. **iSixSigma — Dhiman Banerjee, "SIPOC: Beyond Process Mapping"**
   https://www.isixsigma.com/dictionary/sipoc/
   - Definition of the SIPOC elements (Supplier, Input, Process, Output, Customer) used as a high-level boundary map.
   - → feeds Phase 1 Q1.4 and the SIPOC note in [frameworks.md](frameworks.md).

6. **Standard frameworks referenced (well-established practice, not a single page):**
   - **RACI** (Responsible / Accountable / Consulted / Informed) — decision-rights model used in [frameworks.md](frameworks.md) and Phase 2B.
   - **Definition of Done / Definition of Ready** — Agile practice used in the software-dev add-ons.
   - **BPMN 2.0** — process-modeling notation (introduced via the Lucid source above).
